I. MỤC TIÊU CỐT LÕI & CHIẾN LƯỢC TỐI ƯU DỰ ÁN VNXBOXMục tiêu của dự án là xây dựng một Universal B2B Local AI Platform (Trợ lý AI nội bộ cho doanh nghiệp) chạy 100% Local-First / Offline, đáp ứng các tiêu chuẩn khắt khe:Triệt tiêu ảo giác số học (Zero-Hallucination Math): AI không bao giờ được tự nhẩm tính số liệu tài chính, giá vốn, quy đổi tuổi vàng hay tỷ lệ chiết khấu. Mọi phép toán phải được trích xuất thành mã Python và đẩy vào Secure Python Sandbox Engine thực thi để trả kết quả chính xác 100%.Quản trị Tri thức Phân cấp Cây (Taxonomy & Deep Traceability): Quản lý tri thức theo cấu trúc sâu [Lĩnh vực] > [Nghiệp vụ] > [Chương] > [Điều] > [Mục / Sheet]. Khi trả lời phải dẫn đường link / thẻ citation 1-Click để Admin mở đúng vị trí chỉnh sửa trong Dashboard.Tra cứu Đa tầng (Multi-Tier Intent Routing & Anti-Hallucination):Tier 1: Đón đầu ý định người dùng bằng bộ câu hỏi mẫu (FAQ Radar).Tier 2: Tra cứu kết hợp Hybrid Search (Dense bge-m3 + Sparse BM25).Tier 3: Ngưỡng an toàn chống ảo giác (Similarity Score < 0.70 $\rightarrow$ Từ chối đoán mò, cảnh báo thiếu dữ liệu).Bảo tồn Cấu trúc Bảng (Sheet-Aware & Table Structure Preserving): Bóc tách file Excel/Word/PDF không làm nát cấu trúc dòng/cột. Giữ nguyên dạng Markdown Table hoặc Flattened Key-Value để giữ quan hệ dữ liệu.II. ĐÁNH GIÁ REFACTORING VÀ BỔ SUNG CẦN THIẾT CHO MODEL (models.py)File models.py hiện tại của mày đã phủ được khoảng 85% khung lưu trữ cơ bản (KnowledgeChapter, KnowledgeFAQ, KnowledgeHistory, ChatSession, ChatMessage).Tuy nhiên, để đáp ứng trọn vẹn lộ trình Phase 2 & Phase 3, mày cần bổ sung/chỉnh sửa 3 điểm quan trọng sau trong models.py:Python# File: vnxbox/apps/knowledge/models.py (hoặc đường dẫn app tương ứng của mày)

# 1. Sửa lỗi cú pháp string bị rớt dòng ở ChatSession.__str__
class ChatSession(models.Model):
    # ...
    def __str__(self):
        return f"Session {self.session_id} - {self.title}"

# 2. Bổ sung trường vector_id/indexed_at vào KnowledgeChapter để quản lý đồng bộ Auto Re-Indexing
class KnowledgeChapter(models.Model):
    # ... (các trường hiện tại của mày) ...
    is_indexed = models.BooleanField(default=False, help_text="Đã được vectorize và lưu vào Vector DB chưa")
    last_indexed_at = models.DateTimeField(blank=True, null=True, help_text="Thời điểm đồng bộ Vector gần nhất")

# 3. Bổ sung trường embedding / vector reference vào KnowledgeFAQ để phục vụ Intent Routing (Tier 1)
class KnowledgeFAQ(models.Model):
    # ... (các trường hiện tại của mày) ...
    faq_vector_id = models.CharField(max_length=255, blank=True, null=True, help_text="ID của vector đại diện câu hỏi mẫu trong ChromaDB/Vector DB")
III. TỆP NẦY CẦN VIẾT/NÂNG CẤP TIẾP THEO (STEP-BY-STEP)Để bước sang Phase 2 (Ingest Pipeline & Taxonomy Parser), mày cần tạo và triển khai file sau đây đầu tiên:📄 Tệp tiếp theo cần tạo: ingestion/parsers.py(Đường dẫn gợi ý: vnxbox/apps/ingestion/parsers.py)Vai trò của file parsers.py:File này chịu trách nhiệm bóc tách thô và giữ nguyên cấu trúc các tệp tin đầu vào (.xlsx, .xls, .docx, .pdf, .csv) trước khi đẩy qua bộ phân rã Taxonomy.Nội dung triển khai trong ingestion/parsers.py:ExcelSheetAwareParser:Đọc file Excel nhiều Sheet bằng pandas / openpyxl.Tách từng Sheet thành 1 khối độc lập.Chuyển đổi dữ liệu bảng thành Markdown Table chuẩn (| Header 1 | Header 2 |) để lưu trực tiếp vào trường content của KnowledgeChapter.WordHeadingParser:Đọc file .docx bằng python-docx.Nhận diện các thẻ Heading (# Heading 1, ## Heading 2, Chương..., Điều...) để tách đoạn văn bản kèm giữ ngữ cảnh cha-con.PDFDocumentParser:Sử dụng pdfplumber hoặc tích hợp OCR Local (EasyOCR / Qwen2-VL) để bóc tách chữ + bảng từ file PDF Scan.📋 Sơ đồ thứ tự triển khai các file tiếp theo của Phase 2 & 3:🟢 Tệp 1 (TẠO NGAY): ingestion/parsers.pyNhiệm vụ: Bóc tách file Excel/Word/PDF giữ nguyên cấu trúc bảng & sheet.🟡 Tệp 2: ingestion/taxonomy.pyNhiệm vụ: Nhận dữ liệu từ parsers.py, gọi AI Local để tự trích xuất Metadata (domain_name, sub_domain, chapter_code, article_code) và tự gắn khối Context Injection Prefixing trước khi save() vào KnowledgeChapter.🟡 Tệp 3: ingestion/faq_generator.pyNhiệm vụ: Đọc từng KnowledgeChapter mới tạo, gọi AI đóng vai khách hàng/nhân viên sinh 10–20 câu hỏi mẫu và lưu hàng loạt vào bảng KnowledgeFAQ.🔵 Tệp 4 (Phase 3): search/hybrid_engine.pyNhiệm vụ: Dựng luồng tra cứu 3 tầng (FAQ Matching $\rightarrow$ Dense bge-m3 + Sparse BM25 $\rightarrow$ Score Threshold $\ge 0.70$).
